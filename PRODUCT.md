# Product

## Register

product

## Users

Telecom engineers, RF planning students, geospatial simulation reviewers, and technical portfolio evaluators use A.T.O.M to inspect how cellular signals behave across Ankara's dense urban fabric. They are usually comparing network technologies, selecting towers, changing antenna parameters, and judging whether an optimized beam points toward meaningful demand rather than empty distance.

## Product Purpose

A.T.O.M, Ankara Telecom Optimization Model, is a local-first RF propagation and antenna optimization dashboard. It simulates 4G LTE, 5G mmWave, and 6G Sub-THz propagation using static tower and building data, then visualizes ray attenuation, obstruction, and demand-aware azimuth choices on an interactive map. Success means users can understand the physical model, trust the data quality, and adjust simulation controls without losing spatial context.

## Brand Personality

Technical command center: precise, credible, calm, and high-signal. The product should feel like a professional telecom planning instrument rather than a marketing demo, while still having enough visual polish to communicate the ambition of the project.

## Anti-references

Avoid generic SaaS dashboards, decorative card grids, oversized landing-page hero layouts, neon sci-fi clutter, low-contrast gray-on-tint text, and UI that hides the map behind chrome. Avoid implying more real-world certainty than the static OSM/OpenCellID-derived dataset can support.

## Design Principles

1. Map first, controls second: the user should always understand the active tower, beam, and coverage state.
2. Surface model confidence: data quality, demand scores, and optimizer breakdowns should be visible enough to explain the result.
3. Make RF physics legible: frequency, power, beam width, azimuth, and range should read like connected planning parameters.
4. Prefer operational density over decoration: every visual element should help scanning, comparison, or repeated simulation.
5. Keep the system honest: limitations from static datasets and synthetic demand should appear as diagnostics, not hidden caveats.

## Accessibility & Inclusion

Target WCAG AA. Use strong contrast for controls and map-adjacent status text, keyboard-accessible buttons and range inputs, clear focus states, reduced-motion fallbacks, and color choices that do not rely on hue alone for important RF or data-quality meaning.
