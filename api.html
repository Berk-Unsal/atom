    API Reference

    A.T.O.M exposes a comprehensive REST API for programmatic access to all simulation and optimization features.

    Base URL

    http://localhost:8080/api

    Or in production:

    https://your-domain.com/api

    Authentication

    A.T.O.M v1.0 has no authentication (suitable for internal/private networks). For production deployments, add authentication via reverse proxy (e.g., nginx with OAuth2).

    Response Format

    All responses are JSON with consistent structure:

    Success Response

    {
  "success": true,
  "data": { /* ... */ },
  "timestamp": "2026-06-20T14:30:00Z"
}

    Error Response

    {
  "success": false,
  "error": "Invalid frequency: must be one of [4G, 5G, 6G]",
  "timestamp": "2026-06-20T14:30:00Z"
}

    Endpoints

    Health Check

    Endpoint: GET /health

    Check if the API is running and all data is loaded.

    Response:

    {
  "success": true,
  "data": {
    "status": "healthy",
    "buildings_loaded": 12047,
    "towers_loaded": 287,
    "version": "1.0.0"
  }
}

    Status Codes: - 200 OK - API is healthy - 503 Service Unavailable - Data not yet loaded (startup)

    Get Buildings

    Endpoint: GET /buildings

    Retrieve all building geometries as GeoJSON.

    Query Parameters: None

    Response:

    {
  "success": true,
  "data": {
    "type": "FeatureCollection",
    "features": [
      {
        "type": "Feature",
        "properties": {
          "building": "concrete",
          "name": "Ankara Central Tower",
          "height": 45
        },
        "geometry": {
          "type": "Polygon",
          "coordinates": [[[33.8, 39.9], [33.801, 39.9], ...]]
        }
      }
    ]
  }
}

    Performance: ~100 MB response, consider client-side filtering.

    Get Towers

    Endpoint: GET /towers

    Retrieve all 5G/4G tower locations.

    Query Parameters: - frequency (optional): Filter by band (4G, 5G, 6G)

    Response:

    {
  "success": true,
  "data": {
    "type": "FeatureCollection",
    "features": [
      {
        "type": "Feature",
        "properties": {
          "tower_id": "ankara_001",
          "frequency": "5G",
          "operator": "Türk Telekom",
          "coordinates": [33.8, 39.9]
        },
        "geometry": {
          "type": "Point",
          "coordinates": [33.8, 39.9]
        }
      }
    ]
  }
}

    Simulate Propagation

    Endpoint: POST /simulate

    Run RF propagation simulation with given parameters.

    Request Body:

    {
  "tower_id": "ankara_001",
  "frequency": "5G",
  "azimuth": 45,
  "beam_width": 65,
  "power_dbm": 40,
  "grid_size": 10
}

    Parameters:

    Parameter Type Range Required Description
    tower_id string - Yes Tower identifier (from /towers)
    frequency string 4G, 5G, 6G Yes Frequency band
    azimuth number 0 - 360 Yes Antenna direction (degrees)
    beam_width number 5 - 180 Yes Sector width (degrees)
    power_dbm number 0 - 50 No TX power (default: 40 dBm)
    grid_size number 5, 10, 20 No Coverage grid resolution (meters, default: 10)

    Response:

    {
  "success": true,
  "data": {
    "type": "FeatureCollection",
    "features": [
      {
        "type": "Feature",
        "properties": {
          "frequency": "5G",
          "azimuth": 45,
          "rx_dbm": -75,
          "signal_quality": "good",
          "distance": 1200
        },
        "geometry": {
          "type": "LineString",
          "coordinates": [[33.8, 39.9], [33.805, 39.91]]
        }
      }
    ]
  },
  "metadata": {
    "ray_count": 89456,
    "compute_time_ms": 1847
  }
}

    Status Codes: - 200 OK - Simulation completed successfully - 400 Bad Request - Invalid parameters - 404 Not Found - Tower not found - 500 Internal Server Error - Simulation error

    Performance: - Typical response time: 1-3 seconds (depends on grid size) - Maximum rays: 100,000+ per request - Timeout: 30 seconds

    Optimize Antenna Placement

    Endpoint: POST /optimize

    Automatically find the optimal antenna azimuth for maximum coverage.

    Request Body:

    {
  "tower_id": "ankara_001",
  "frequency": "5G",
  "beam_width": 65,
  "power_dbm": 40
}

    Parameters:

    Parameter Type Required Description
    tower_id string Yes Tower identifier
    frequency string Yes Frequency band
    beam_width number No Sector width (default: 65°)
    power_dbm number No TX power (default: 40 dBm)

    Response:

    {
  "success": true,
  "data": {
    "optimal_azimuth": 42,
    "coverage_area": 2847539,
    "iterations": 72,
    "algorithm": "sweep_and_score",
    "optimization_time_ms": 248,
    "simulation": {
      "type": "FeatureCollection",
      "features": [ /* GeoJSON at optimal azimuth */ ]
    }
  }
}

    Response Fields:

    Field Description
    optimal_azimuth Recommended antenna direction (0-360°)
    coverage_area Sum of squared distances above threshold (higher = better)
    iterations Number of azimuths tested (72 for 5° resolution)
    optimization_time_ms Computation time in milliseconds
    simulation GeoJSON output at optimal azimuth

    Status Codes: - 200 OK - Optimization succeeded - 400 Bad Request - Invalid parameters - 404 Not Found - Tower not found - 500 Internal Server Error - Optimization error

    Performance: - Typical response time: 3-5 seconds - Parallelization: Uses all available CPU cores - Timeout: 60 seconds

    Usage Examples

    Example 1: Get Health Status

    curl -X GET http://localhost:8080/api/health

    Example 2: Simulate 5G Coverage

    curl -X POST http://localhost:8080/api/simulate \
  -H "Content-Type: application/json" \
  -d '{
    "tower_id": "ankara_001",
    "frequency": "5G",
    "azimuth": 90,
    "beam_width": 65,
    "power_dbm": 40,
    "grid_size": 10
  }'

    Example 3: Auto-Optimize Antenna

    curl -X POST http://localhost:8080/api/optimize \
  -H "Content-Type: application/json" \
  -d '{
    "tower_id": "ankara_001",
    "frequency": "5G",
    "beam_width": 65,
    "power_dbm": 40
  }'

    Example 4: Fetch All Towers

    curl -X GET "http://localhost:8080/api/towers?frequency=5G"

    Client Libraries

    Go Client

    import "github.com/your-org/atom-client-go"

client := atom.NewClient("http://localhost:8080")

result, err := client.Simulate(context.Background(), &atom.SimulateRequest{
    TowerID: "ankara_001",
    Frequency: "5G",
    Azimuth: 45,
    BeamWidth: 65,
})

    Python Client

    import requests

client = requests.Session()
response = client.post(
    'http://localhost:8080/api/simulate',
    json={
        'tower_id': 'ankara_001',
        'frequency': '5G',
        'azimuth': 45,
        'beam_width': 65,
        'power_dbm': 40
    }
)

data = response.json()
print(data['data'])

    JavaScript Client

    async function simulateRF(params) {
  const response = await fetch('http://localhost:8080/api/simulate', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(params)
  });

  const data = await response.json();
  return data.data;
}

const coverage = await simulateRF({
  tower_id: 'ankara_001',
  frequency: '5G',
  azimuth: 45,
  beam_width: 65,
  power_dbm: 40
});

    Rate Limiting

    A.T.O.M v1.0 has no built-in rate limiting. For production:

    1. Deploy behind reverse proxy (nginx, HAProxy)
    2. Add rate limiting at proxy layer
    3. Implement API key authentication
    4. Track per-client request counts

    Recommended limits: - 10 requests/second per API key - 1000 requests/day per API key - 100 concurrent requests max

    Versioning

    Current API Version: 1.0

    Future versions will: - Add webhook support for async simulations - Support batch optimization requests - Include terrain elevation models - Add custom propagation model endpoints

    Breaking changes will increment major version (e.g., /v2).

    Troubleshooting

    503 Service Unavailable

    Cause: Data not yet loaded at startup

    Solution: Wait 5-10 seconds and retry

    400 Bad Request

    Cause: Invalid parameter values

    Solution: Check parameter types and ranges in documentation

    500 Internal Server Error

    Cause: Computation timeout or backend crash

    Solution: - Check logs: docker logs atom-simulator - Reduce grid_size for faster computation - Increase timeout values if needed

    Slow Response Times

    Cause: Overlapping concurrent requests

    Solution: - Reduce grid size (10 m → 20 m) - Increase container resources (CPU/RAM) - Implement client-side request batching
