# Concept 4G.2 receiver/noise audit

Captured 2026-09-18 before any Concept 4G.2 production edits. The worktree
already contains the completed Concept 4G.1 changes; this audit treats those
changes as the current compatibility baseline and does not reset them.

## Current receiver contract

- `CellRFProfile.receiver_sensitivity_dbm` is the only receiver threshold
  input. `DefaultCellRFProfile` and API request defaults set it to `-115 dBm`.
- The existing profile has no sensitivity mode, receiver noise bandwidth,
  receiver-specific noise figure, required SNR, or receiver margin.
- `receiver_sensitivity_dbm` is per normalized cell profile. The request-level
  `bandwidth_mhz` is copied into a profile, and network/interference requests
  can override it per cell through `rf_profile.bandwidth_mhz`.
- Static ray termination uses the per-cell threshold at the start of a ray,
  after each wall event, and at a segment-end crossing. The effective
  comparison is strict: signal is usable only when `received_power_dbm >
  receiver_sensitivity_dbm`; equality terminates/does not count as usable.
- Coverage surfaces retain raw received power values, including values below
  sensitivity. Sensitivity is used only for the `below_sensitivity` statistic;
  NoData is reserved for radius/beam geometry exclusion.
- Building-entry low/high indoor serviceability currently compares
  `outdoor_rx - entry_loss` to receiver sensitivity. Outdoor building serving
  remains a separate strict `> -100 dBm` building-service threshold.
- Optimization uses the static-ray terminal reach and building coverage
  generated by the same strict receiver threshold; it does not directly use
  interference.

## Existing interference/noise semantics

- Interference analysis admits a carrier only when its received carrier power
  is strictly greater than the cell profile sensitivity.
- Interference has a separate request-level `noise_figure_db` (default 7 dB).
  It computes `ThermalNoisePerREDBm(SCS, NF) = -174 + 10 log10(SCS_Hz) + NF`
  using a technology/bandwidth preset (LTE CRS or NR SS), then forms SINR and
  RSRQ from linear-power sums.
- The interference preset bandwidth is not a receiver noise-equivalent
  bandwidth: it selects SCS/resource-block metadata and the RSRP conversion.
  The per-cell RF channel bandwidth remains an independent profile field.
- Interference is not included in the current receiver-sensitivity threshold
  and must remain separate in 4G.2. No duplicated thermal-noise term was found
  in static propagation or building-entry evaluation; the only current
  thermal-noise implementation is the interference per-RE helper.

## Integration audit

The single receiver-threshold evaluator introduced by 4G.2 must be resolved
once per effective cell profile and reused by:

1. static ray start/wall/crossing termination and usable reach;
2. building-entry low/high serviceability (while retaining the separate
   building-service threshold);
3. surface below-sensitivity statistics/threshold metadata without clipping
   raw values;
4. interference signal admission/receiver diagnostics without changing the
   RSRP/SINR/RSRQ equations; and
5. link-budget/propagation diagnostics as a receiver section and link margin.

The derived receiver bandwidth must be explicit in Hz, or explicitly report
the documented `channel_bandwidth` approximation when it is sourced from the
profile channel bandwidth. It must not silently consume interference SCS,
resource blocks, load, or co-channel power.

## Reference basis selected for implementation

The implementation will use the deterministic first-principles convention

```text
N0 = -174 dBm/Hz (rounded 290 K reference convention)
Nfloor = N0 + 10 log10(Bnoise_Hz) + NF_dB
Sensitivity = Nfloor + RequiredSNR_dB + ReceiverMargin_dB
```

The exact SI constant is `k_B = 1.380649e-23 J/K`; the product `k_B * 290 K`
converts to the rounded `-174 dBm/Hz` convention used by the existing
interference helper and by the independent fixtures. This is an engineering
noise-floor convention, not a 3GPP UE conformance sensitivity claim. Derived
profiles must carry bandwidth source, assumptions, and applicability metadata.

References: [NIST SI redefinition of the kelvin](https://www.nist.gov/si-redefinition/kelvin/kelvin-boltzmann-constant),
[NIST SP 330 section 2](https://www.nist.gov/pml/special-publication-330/sp-330-section-2),
and [ETSI TR 103 688 Annex E](https://www.etsi.org/deliver/etsi_tr/103600_103699/103688/01.01.01_60/tr_103688v010101p.pdf).
