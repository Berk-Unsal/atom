    0.13.0 - 2026-10-22

    Added

    • Add an opt-in desktop API sidecar control protocol: the host supplies inherited control pipes, the sidecar binds to loopback, reports lifecycle/readiness events, authenticates each request with a per-launch token and exact host/origin, and drains cleanly when the host closes the pipe. Default web, Docker, and CLI modes are unchanged; this is sidecar support, not a packaged desktop application.
    • Add a Figma-authored ATOM signal-path icon with scalable SVG, transparent and monochrome marks, a small-size favicon, PNG exports, and Windows ICO/macOS ICNS assets. Refresh the app, README and documentation icon and provide a reproducible export and validation script.
    • Redesign generated Markdown and printable reports around one semantic model: a decision summary with evaluation completeness, explicit KPI units and populations, deterministic interpretation, numbered collision-aware maps sampled to 300 RF segments, grouped common/reference RF profiles with per-Cell deviations, separated source/generator provenance and an engineering appendix. Add UTC timestamps and shared report filename stems, preserve retained artifact bytes and historical unknowns, document reading/print settings, and verify real A4 PDFs and accessibility. RF, optimization, score and persistence contracts are unchanged.
    • Show where two compatible network plans differ: Results → Compare offers Show where they differ for saved network Versions, the current network plan, or an optimization's baseline and solutions on the current dataset and model. A new POST /api/compare-network endpoint evaluates both plans (one protected RF request) and returns demand buildings newly served or lost and buildings whose overlap changed, with counts that reconcile exactly with the aggregate KPI deltas and a bounded building list. The map layer has a labeled legend, and reports include the counts and a static map.
    • Place and manage co-located multi-sector Cells as one site group: Inventory → Place site adds N Cells (default 0/120/240°, editable) at one map point that move together. Each remains an ordinary Cell in every request (sector azimuths are its default azimuth); editing one member changes only that Cell unless you apply its RF profile to the site, and Ungroup site restores independent Cells. Projects round-trip the optional siteGroupId/sectorAzimuthDeg fields without a file version change, and older files import unchanged.
    • Export a local review package for the current saved Version from Review → Report: one .zip with the HTML and Markdown reports, the project file, the report map and a manifest.json (file SHA-256 hashes, dataset and model identity, Version/Run lineage, limitations). It is generated in the browser with no RF request, checks its own manifest before downloading, follows the shareable filename rule, and refuses unsaved drafts with guidance to save a Version.
    • Report network KPIs inside one drawn area of interest: with Report KPIs inside the drawn area on, Evaluate and Optimize Network add served demand, residential buildings and overlap inside the area beside the network-wide values in Results and reports. The API gains an optional aoi polygon (validated like search_polygon) and stats.area_of_interest, a subset aggregation of the same per-building results; objectives, scores and the scenario fingerprint are unchanged.
    • Show a dismissible first-run card before any project work exists: one sentence on what A.T.O.M does, Run the pre-selected sector, Open sample network project and a Planning glossary link. The sample opens as a new project without changing existing work and selects the two Cells nearest the pre-selected sector, so Evaluate Network is one more click. Dismissal is remembered in this browser.
    • Add a keyboard-operable trade-off chart to Results → Solutions: plot the retained Pareto frontier on any two objectives (or the optimization score), see Recommended and Selected marked by shape and label, and inspect a solution by choosing its point without an RF request. A table lists the plotted solutions, and the solution list shows the top five with a Show all control.
    • Expose candidate Cell recommendation as an explicit Find an additional Cell action in Network mode (Propagation and Results → Candidates) that lists its prerequisites before you run it. Candidates keeps its own Results tab beside Solutions after a Pareto optimization, and Draw search area keeps the selected Cells instead of replacing them with the eight nearest. Candidate scoring and the request are unchanged.
    • Compare any two states from Results → Compare, even while a network result is shown: pick the current result, the optimization baseline or recommended solution, the inspected Pareto alternative, or any saved Version, and see KPI deltas, input differences and an A/B map switch in one view. Pairs with a different dataset or model version show an incompatibility notice instead of deltas, Baseline vs Recommended stays the default after an optimization, and Plan → Scenarios links to the same view.
    • Explain normalized network scores, Pareto trade-offs, local reranking and explicit apply/search actions with accessible Results help.
    • Define OpenAPI response schemas for readiness and batch experiment discovery, with shared response-contract fixtures checked against the existing handlers.
    • Explain a single-sector result before its metrics: one line built from the returned fields separates ray blockage from demand coverage gaps and names the receiver-sensitivity, planning-radius and building-service thresholds, with an "About these metrics" disclosure.
    • Bring completed results into view: Run Sector, Auto-Optimize Sector, Evaluate Network, Optimize Network and finished area selections fit the map to the selected Cells and their planning radius, unless you moved the map during the run; the Interference tool now summarizes a completed analysis with an Open in Results action.
    • Apply a Pareto alternative from an optimization run on an unsaved working draft: the Run's exact starting plan is saved as the source Version first (refused if Cells, RF settings or inventory changed), and Solutions marks the solution already loaded in the draft.

    Fixed

    • Build with Go 1.26.10 to include the fix for GO-2026-6809 in crypto/x509, which govulncheck reports for Go 1.26.9.
    • Update the frontend build tooling to Vite 6.4.5 and Vitest 4.1.12 for the launch-editor command-injection and mock-registration advisories reported by npm audit.
    • Restore result context after a reload: the newest retained Run that computed exactly the restored plan (canonical request, dataset and model version, the same rule as applying a draft Pareto alternative) is shown as HISTORICAL with its summary, and a working draft offers Restore map layers as the only RF request. Saving a Version right after a matching run records that Run as its source in Version metadata, Results explains when no Run applies, live network evaluations no longer borrow an earlier optimization Run, and the command bar never shows Ready with UNAVAILABLE.
    • Give CSV Measurement Validation its own section in Review → Data instead of a collapsed Research disclosure, and rename the Analyze → RF Diagnostics campaign tool to Research campaign evidence so no two tools share the measurement-validation name. Boundary copy, the six-Cell limit and the explicit apply confirmation are unchanged.
    • Distinguish a planning-mode switch from an input change: switching Single ↔︎ Network without changing inputs shows a neutral OTHER MODE state naming the Result's mode instead of STALE, while any input change, and any identity or fingerprint mismatch, still shows STALE. Run labels lead with type · Cells · headline metric · time in the command bar, Results and Run history, with the Run ID kept in details. The header, Results and Scenarios share one Version-state wording ("No saved Version", "Version N", "Version N · Unsaved changes"). New Scenarios are named from the plan mode ("Sector plan N", "Network plan N"); existing names never change.
    • Keep map chrome out of map work at desktop sizes: the Map key fades and stops capturing clicks while you draw an area, place a Cell or pick a path endpoint, and scrolls instead of clipping; command-bar segments truncate instead of overprinting "RF details"; Results tabs wrap so every tab stays visible; a drawer heading focused on open is underlined instead of boxed. Linux screenshot baselines (light/dark × 1440/1280/1024) now cover first run, Results and Solutions.
    • Explain request failures with recovery steps: an unreachable API names its address and offers Retry for the startup loads, server errors keep their detail with retry guidance, the RF deadline (504) suggests retrying or reducing the plan, and unreadable responses are reported; out-of-range Setup values show inline errors with aria-invalid, and the invalid-profile prompt names and opens Setup or Inventory according to where the value lives.
    • Name report and project downloads <project>-<scenario>-v<N>-<yyyymmdd>[-report] instead of report IDs, drop the duplicated single-cell RF section and unconfigured constraint rows, replace inline SVG in Markdown reports with a pointer to the HTML/PDF report (which keeps the map), and show the same Scenario/Version/Run lineage on the Report source card and the stored Report.
    • Close the project menu with Escape and return focus to its trigger without closing the open tool, name the trigger after its project, use one "Save Version" label for the visible text, accessible name and progress, rename the command-bar cell-selection action to "Select 2+ cells", and add an axe accessibility smoke check for the project menu, Setup and Results.
    • Show result units exactly as produced (dBm, m), present a zero-gap result neutrally with an unavailable Worst Rx, use Cell instead of tower in selection, error and report copy, and state the nearest-to-centre rule when a drawn area holds more Cells than the network limit.
    • Carry an applied optimization solution's azimuths into the plan. Numeric Cell IDs let the previously saved azimuths win, so the next run used the old values; Versions applied before this fix now restore the solution azimuths.
    • Keep the Terminology tab visible across documentation pages and highlight it when selected.
    • Explain recovery after portable-project size and complexity limits, preserve current result context on rejected imports, and link to the unchanged format limits.
