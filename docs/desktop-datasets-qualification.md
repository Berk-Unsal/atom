# Desktop dataset-pack qualification

Scope: #155, Electron desktop capability on the existing shared React/Go product. This is implementation/qualification evidence, not a public distribution or support claim. The initial local native run passed on macOS arm64 with a dirty implementation worktree; a frozen-source record and native CI qualification are still required.

## Implemented boundary

Data → Add Dataset Pack or Add Dataset Manifest selects a source through the OS chooser. The native task displays the canonical manifest identity, sources, licenses, exact declared byte size, manifest SHA-256 and declared layer hashes before registration. Managed copy is the default; reference-in-place is an explicit advanced choice. Dialog choices are automated in the native suite; OS chooser appearance is not qualified.

The owned Go executable's additive `--validate-dataset-json` mode performs complete existing `LoadDatasetPack` validation without a listener or transport credential. The original validator CLI, manifest schema, optional-layer interpretation and RF model remain unchanged. The host streams bounded declared files, rejects traversal/escape/nonregular inputs, verifies SHA-256 and source stability, and issues an opaque two-minute selection ticket. Native limits are 1 MiB manifest, 2 GiB per layer, 4 GiB total pack and five minutes per owned canonical validation process. These are explicit native resource limits, not a new dataset format.

Managed copy creates a private staging directory, copies only declared files, flushes files/directory entries where supported, revalidates the complete stage, and atomically renames it before saving the existing native settings registry. Canceled/failed stages are removed. A complete but unregistered directory after a later settings-write failure may remain; it is not implicitly activated or discovered. No external source is mutated or deleted. Existing complete identical managed content is revalidated/reused; an identical reference can be explicitly located at a new folder. Ambiguous same-ID/different-manifest content is refused.

An ephemeral private 0600 JSON file supplies approved roots and their manifest hashes to the existing Go dataset runtime only in inherited-pipe desktop mode. It is derived from native settings, not another persistent domain store. Generic renderer HTTP cannot invoke dataset switching; five exact-document typed IPC operations own status, chooser, install, activation and cancel. A sixth preload capability subscribes to Data menu commands. Renderer inputs contain IDs/tickets/modes, never arbitrary source paths or transport credentials.

Activation revalidates the source and expected manifest hash, then uses the existing canonical Go atomic switch. Go checks cancellation before committing a loaded replacement and retains old in-flight snapshots. References revalidate at activation and process startup; keep referenced folders immutable while in use. This does not introduce a continuous filesystem watcher or alter the shared file-serving API semantics. Missing/moved startup references keep the shared UI and native Data controls available and require explicit recovery; there is no silent default-pack substitution. A post-commit settings/response failure reports the actual active/registered state rather than claiming a rollback. Activation clears current rendered results through the existing shared workflow and preserves original project dataset ID/version/hash bindings. Retained project inventories may therefore remain visible with the existing dataset-mismatch indication; they are not evidence that the runtime switched back.

## Local functional evidence

- Full Go vet/race tests passed; focused registry tests cover private/bounded files, symlink/hardlink refusal, ambiguous IDs, changed/moved references, same-ID revalidation, cancellation and old-snapshot preservation.
- 103 host tests and 782 frontend tests passed before the final qualification-only refinements; lint and production build passed. Host tests include managed copy, declared-file selection, hashes, traversal/symlink escape, stale tickets, cancellation, real permission failure, incomplete-stage cleanup, explicit locate and truthful post-commit errors.
- The real native suite passed managed copy and source removal, actual canonical Go activation, changed-reference rejection, conflicting-ID rejection, selected-pack persistence across relaunch, missing-reference startup UI, same-identity locate/recovery with a new owned generation, cancellation/reaping of the observed owned validator, pending-operation Quit, and zero dataset-action RF POSTs.
- Light wide/minimum-width and dark minimum-width task captures were inspected. The first offline capture exposed a map-key overlap and noninteractive inherited feedback style. Native feedback now reserves space for the map key and its explicit Retry button passes a real unforced click; confirmation captures show both readable. No broader redesign was performed.

## Provider evidence and limits

Native light/dark use OSM Standard with visible contributor attribution and a distinct root-version User-Agent; native CSP/network policy permits only valid OSM raster tile image coordinates. Browser Alidade defaults/theme choices remain unchanged. Denied/offline tile tests retain map overlays and attribution and offer explicit same-provider retry. Routine native and development-loop tests block public OSM from process startup; they do not use an upstream service as an automated map fixture.

The explicit macOS provider probe passed a real native 256×256 PNG from one fixed OSM tile, HTTP 200, no credentials, no localhost/Referer spoofing and no `Cache-Control: no-cache`. The response supplied HTTP caching/ETag metadata; the same normal native HTTP cache returned `fromCache: true` after a real app relaunch. Only that one tile URL was allowed by additional test-side deny instrumentation, without changing production cache/provider behavior. The probe is intentionally excluded from routine CI and is not a bulk load, service-availability guarantee or offline-map feature.

Both platforms' native dataset suites, a frozen local record, independent performance budgets and maintainer review remain required. Intel Mac, Wayland and clean-machine installers retain their separate roadmap gates. The exact default pack's [redistribution review](desktop-data-redistribution-review.md) remains pending; no public packaged-data approval is claimed.
