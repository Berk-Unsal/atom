# Production macOS Print qualification

Status: implementation prepared on 2026-11-20 for #156/#158/#159. Actual hosted outcomes are pending; successful supporting tests are not OS-surface acceptance.

The existing native macOS package matrix builds the committed production app for arm64 and Intel. The follow-up starts Apple's built-in `ippeveprinter` with a private spool/certificate directory and explicit localhost binding, verifies both listener addresses are loopback, creates an unshared `AtomQualification` CUPS queue, and selects it as the disposable VM's default before launching the app. It refuses an existing queue of that name. The receiver retains the real submitted PDF for private verification. Cleanup removes only the owned queue, restores any previous default, terminates the owned receiver and removes the private test files. Printer setup is guarded by macOS, non-root and `GITHUB_ACTIONS=true`; personal-machine execution is refused.

The packaged app is copied outside the repository under a Unicode/space path and made read-only. It uses private native home/recovery storage, ordinary sandboxed launch and the existing tile-blocking qualification helper. One explicit Sector Run and Save Version prepare actual report lineage. No report output, Electron print method, native response, filesystem or RF operation is replaced.

An external JavaScript for Automation helper uses System Events against the exact packaged app PID and bundle ID. It observes actual native sheets/dialogs, requires one enabled Cancel, one enabled Print and the collapsed selected qualification-printer control within panel bounds, then sends one native accessibility press. It refuses ambiguous/disabled controls, renderer-only Print buttons and unexpected destinations. An uncertain input failure propagates without retry. Only bounded native markers/control frames are recorded; the report document's accessibility text is excluded.

The intended flow checks that Cancel leaves existing retained artifact hashes and an empty queue unchanged. A second actual Print must complete exactly one CUPS job and produce one bounded PDF in the owned receiver spool. Text extraction diagnostics and a first-page raster/OCR verify the Project, Run and report labels. Ordinary Quit must reap the app/owned Go children, and the installed bundle inventory must remain unchanged. Only source-bound receipts, failure diagnostics, display metadata and the rendered test page are uploaded; generated PDF/project/app/default-data files are excluded.

The runner image's [published provisioning](https://github.com/actions/runner-images/blob/main/images/macos/scripts/build/configure-tccdb-macos.sh) preauthorizes `/usr/bin/osascript` for accessibility/automation. The workflow still has to demonstrate current-image access; it does not change TCC/SIP policy. Receiver options follow [Apple CUPS's ippeveprinter manual](https://github.com/apple/cups/blob/master/man/ippeveprinter.1). Initial working-plan restoration and a suitable advertised hosted display mode are observed before the Print flow.

Local validation covers the pure native-control selector, non-CI refusal, a no-retry regression for uncertain AXPress failure, JavaScript/JXA compilation, host/docs checks and workflow lint. No local printer or display setting is changed. Hosted native Print, physical output, signed/quarantined downloads, minimum-OS clean machines, original performance budgets and rights/provider/license decisions remain separate gates.

## First hosted observations

[Run 44806823023](https://github.com/Berk-Unsal/atom/actions/runs/44806823023), execution `caab17b362683c518e53ab9e45f89bcf7dbf10c1` from head `70c4fab`, reaches actual native Print Cancel and Print on both arm64 and Intel. Both drivers find the real dialog and selected queue and press the actual controls. Cancel preserves retained bytes and submits no job. The later job completes and its PDF preserves exact Unicode Project and Run text. Both complete flows nevertheless fail before ordinary Quit: English-only OCR reads the rendered Turkish `Çankaya` as `Gankaya`. The actual page is readable; source text extraction already recovers the correct label.

The [scoped first-run record](assets/desktop-macos-print-first-ci.json) retains these failures, native controls, extraction flags, raster hashes and artifact identities. A supporting local reread of each downloaded actual raster with Turkish + English OCR recovers every required label. The workflow now downloads the Turkish model at a fixed upstream commit, verifies its SHA-256 and uses it alongside the installed English model. It does not alter the report, accept misspelled labels or weaken the required rendered-content checks. The model is a CI tool, excluded from app bundles and evidence uploads. A complete hosted rerun remains pending; local OCR success is not a native-flow pass.
