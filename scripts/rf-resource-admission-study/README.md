# Bounded RF resource study (audit only)

This tooling writes counters and a test harness into a **disposable copy**. It never
edits production Go/React code, policy, equations, cache behavior, or persistence.
No admission-system implementation is included. The canonical fixture generator
is reused from `scripts/network-capacity-audit/fixtures.mjs`.

Explicit opt-in, from the repository root:

```sh
python3 scripts/rf-resource-admission-study/prepare.py --run
python3 scripts/rf-resource-admission-study/plans.py
python3 scripts/rf-resource-admission-study/run.py --run --suite endpoints
python3 scripts/rf-resource-admission-study/run.py --run --suite sensitivity
python3 scripts/rf-resource-admission-study/run.py --run --suite high
python3 scripts/rf-resource-admission-study/run.py --run --suite concurrent
python3 scripts/rf-resource-admission-study/run.py --run --suite overlap
python3 scripts/rf-resource-admission-study/run.py --run --suite domains
python3 scripts/rf-resource-admission-study/run.py --run --suite workflows
python3 scripts/rf-resource-admission-study/run.py --run --suite semantics --frequencies 2.6
```

Run suites **serially**. Several supported inputs consume the full unchanged
60-second computation deadline. Each process has a finite scenario list and a
30-minute test watchdog; background jobs have a 120-second study watchdog with
cancellation. A study watchdog is not a production deadline. Aborted jobs and
HTTP 422/504 outcomes must remain in the ledger, not be silently excluded.

`prepare.py --run --eight --workdir /tmp/atom-resource-eight` permits eight cells
only in that disposable copy, retaining all interactive admission guards.
The normal preparation keeps six. Do not use eight for supported-input claims.

Raw request/response JSON and logs stay under `/tmp/atom-resource-study`; the
published ledger removes bodies and records only workload metadata, hashes,
resource measurements, and limitations. Raw files are not product telemetry.

CPU comes from process `getrusage`, including instrumentation/Go GC. Heap and
goroutines are sampled every 50 ms; RSS every 200 ms plus endpoints. Memory is
process-wide and includes the loaded dataset, not exclusive per-request memory.
Forced pre-case GC distinguishes allocation pressure but differs from a warm
long-lived server. Geometry counters are atomic; they perturb throughput.
Spatial candidates count returned footprint matches, not internal R-tree nodes.
`polygon_tests` counts PointInPolygon calls; intersection calls and edge checks
are separate overlapping dimensions. `ray_traces` counts segmented ray traces.
Serialization spans the JSON writer and recorder copy, not just encoder CPU.
Workflow measurement includes test-side parsing used to construct exact optimized
follow-ups. These are observed high-water marks, never certified input-space maxima.

`container.py --run` requires the separate `atom-resource-study` container, built
from the unchanged repository Dockerfile. It measures cgroup CPU and sampled
server RSS with local loopback requests. It neither changes quotas nor uses the
old pre-existing `atom-app` image as this version's evidence.

Supplemental suites `predictors`, `maps`, `bundles`, and `overlap-heavy` are finite
plans generated by `plans.py`. `explanations` first computes a legitimate 360-ray
six-cell optimizer result, then measures its validated cell explanation. No
hand-forged solver result is used. `workers4` is explicitly a **test-only alternate
configuration**: set `ATOM_RESOURCE_WORKERS=4` for that suite; normal runtime stays
one worker. Do not treat the alternate as the normal deployment.

After measurements and checks:

```sh
python3 scripts/rf-resource-admission-study/collect.py
python3 scripts/rf-resource-admission-study/report.py
```

These publication helpers read the completed `/tmp` ledgers and regenerate the
two study documents; they do not run RF work. The report preserves prose before
its generated-block marker. Browser measurements require the existing frontend
Playwright dependency and captured response files; run `node
scripts/rf-resource-admission-study/browser.cjs` after capturing them. This opens
a temporary visible desktop Chromium and closes it when measurements finish.

For the normal-image comparison, explicitly build the unchanged root Dockerfile
as `atom:resource-study`, run the owned `atom-resource-study` container with
`--network none` and no quota overrides, then execute `container.py --run`.
Remove only that owned container after measurement. Linux instrumented test
rows are a separate cross-compiled disposable test binary run in the same image
and quota settings; the published report distinguishes them from normal HTTP.

The final workspace E2E run has an unresolved intermittent bounding-box failure.
The audit records it and preserves the original production tests and UI.
